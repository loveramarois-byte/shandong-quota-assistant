# AI 辅助套价架构

## 产品主链

```text
施工描述
  -> WorkItem 拆分
  -> 类型化属性与否定条件
  -> 每项独立检索清单
  -> 基于 bill_quota_links 加载完整定额关系
  -> PricingProposal（清单 + 多定额角色）
  -> ClarificationQuestion
  -> AI JSON（可选）
  -> ProposalValidator
  -> 人工确认
  -> CSV / JSON / 制表符文本
```

## 真相源与边界

- 清单、定额、版本、专业、单位、关联和页码只信任本地资料库。
- AI 只能选择本轮白名单中的 record ID，不能生成正式编号。
- AI 输出必须先通过 JSON 结构、事项引用、白名单、版本、专业和清单定额关联校验。
- 本地仍有关键缺失条件时，AI 不能把方案标记为 `ready_for_review`。
- 候选排序分数不作为正确概率显示；界面只显示条件吻合度和方案状态。
- 未经人工确认的方案不进入成果导出。

## 核心对象

- `WorkItem`：原文片段、专业、动作、对象、部位、材料、类型化属性、否定条件。
- `ClarificationQuestion`：字段、问题、选项、原因和影响。
- `PricingProposal`：一条清单、零到多条带角色定额、假设、问题、证据和状态。
- `ProposalValidator`：确定性验证清单与定额组合是否合法。

## 当前验证

- `evaluation/datasets/synthetic_v1.jsonl` 提供 30 条不含受限资料的合成描述。
- `evaluation/run.py` 评估事项数量、原文片段、类型化属性和否定条件。
- 合成基线不评估真实套项正确率，也不替代专家黄金案例集。

## 后续工作

- 建立由有权使用资料的造价人员维护的真实黄金案例集。
- 增加每个事项的拆分/合并编辑和方案替换抽屉。
- 为关联表补充 required、互斥组、条件表达式和角色字段。
- 增加方案版本差异、人工修正原因和匿名评测导出。
- 在真实黄金集证明收益后，再考虑 AI reranker 或学习排序。
